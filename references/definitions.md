# definitions.md — ai-app-valuation 语义定义库（查表项）

> 用途：SKILL.md 的语义定义拆分件。SKILL.md 只留流程骨架，本文件是「查表项」——定档/生死/质量分判断时按需查阅，不随每次调用全量加载。
> 版本：v1.7.14（2026-08-31：第四类框架外——AI 驱动资产运营商（美克生案例）；电力交易 AI 赛道锚点（国能日新 §13）；赋能型 AI vs 产品型 AI 判据）

## §1 定档核心判据

**判据不看收费方式（seat/token/outcome 都是表象），看两个维度：①价值来源（软件编排 vs 模型智能本身）②成本结构（COGS 是否随用量线性涨）。毛利只做交叉验证，不单独判档。**

### 「卖的是什么」两维判据
- **价值来源**：客户付费买的是「软件功能」（编排/流程/UI/协作）还是「模型智能本身」（生成/推理/理解能力）？套壳问答 = 智能本身；营销自动化 = 软件功能为主
- **成本结构**：COGS 是否随用量线性涨？涨（模型 API/GPU 按量付）→ 转售智能特征；不涨（软件成本固定）→ 功能特征

### 「自研模型」四档深度（决定二档 vs 三档归属）
| 深度 | 定义 | 资产价值 |
|---|---|---|
| 基座级 | 从预训练做起 | 最强 |
| 后训练级 | SFT/RL 深度定制（非 LoRA 点缀） | 中等 |
| 微调 LoRA 级 | 浅层适配 | 弱 |
| 无自研 | 纯调用 | 无 |

> **三档·自研智能（v1.9.0）**：后训练级/强入口以上即入三档；档内双判据（数据飞轮闭环 + 高切换成本）定位上下沿——下沿 = 自研/入口但飞轮/切换成本不成立（Cursor 有 Composer 但可换 IDE → 15-25x）；上沿 = 飞轮闭环 且 高切换成本（Harvey 法律数据飞轮 + 流程嵌入 → 40-50x）。

### 「毛利结构」五级刻度
| 级别 | 毛利率 | 典型 |
|---|---|---|
| 软件级 | >70% | 群核 82% / 聚水潭 73.6% / 金山 WPS 81% |
| 混合级 | 55-70% | 金蝶 67% / 迅策 61.7% |
| 服务级 | 40-55% | 海致 43% / 商汤 41% |
| 转售级 | 25-40% | 范式智能 34.8% / Liblib <30% |
| 人力级 | <25% | 中软国际 20.4% / 纯外包 |

> 毛利是**结果**不是**原因**：低毛利可能来自（a）转售模型 COGS 高（b）人力重（c）价格战——判档用「价值来源+成本结构」，毛利只做交叉验证防算错。

### 收入质量分层（流量代销剔除纪律 + 渠道灌入识别 v1.13.4）
| 收入类型 | 毛利率 | 例子 | PS 估值意义 |
|---|---|---|---|
| 软件/智能 | 60%+ | AI 应用业务（迈富时 75.2%） | ✅ 核心估值对象 |
| 转售智能 | 25-40% | Liblib（~30%） | ⚠️ 低倍数 6-10x |
| **流量代销** | **<10%** | 迈富时精准营销（5.0%） | ❌ **无意义，剔除或 0.5-1x** |
| **渠道灌入** | 视结构 | Manus 被 Meta 收购期（Ads Manager 7 周接入 1000 万广告主） | ⚠️ **分拆后大概率流失——不算真实独立 ARR** |

**核心红线：流量代销 ≠ 转售智能**。转售智能转售「模型能力」（API 差价 + 平台价值）；流量代销只是媒体流量/货品采买过手（无附加价值、毛利接近 0、无护城河）——**本质是收入规模幻觉**。看到毛利 <10% 的大额收入段：①剔除出 PS 估值（或 0.5-1x 象征性）②估值只针对高毛利段 ③**整体 PS 会被流量代销稀释（迈富时 4.7x 假象 vs 真实 AI 段 8.9x）**——必须先拆再估。

**渠道灌入识别纪律（v1.13.4 Manus 案例）**：大厂并购后的 ARR 暴增要拆「**产品 ARR vs 渠道灌入 ARR**」——前者是估值基础，后者是前任东家的资源（现成客户/流量导入），会随分拆流失。判断：①收入来源是否依赖母体渠道（Ads Manager/应用商店推荐位/生态导流）②分拆/失去渠道后收入留存率预估 ③**买分拆公司前先问：ARR 里有几成是前任东家灌的？** 灌的水会退，退完才是估值基础（Manus：表面 $20 亿 ÷ $4-5 亿 = 4-5x 像捡便宜；真实独立 ARR $1-1.5 亿 → $20 亿 = 13-20x 合理）。

### gross vs net 收入确认（汇量科技教训）
| 确认方式 | 定义 | 例子 | PS 处理 |
|---|---|---|---|
| net 净额法 | 收入 = 平台实际赚的部分 | SaaS 订阅、Liblib 抽成 | ✅ PS 直接用 |
| gross 总额法 | 收入 = 流水过手（流量/交易总额） | 程序化广告（汇量 Mintegral）、交易平台 | ⚠️ **PS 失真，必须用净收入重估** |

> 程序化广告平台（对标 AppLovin）收入常按 gross 确认——收入含媒体流量采购成本，毛利 20% 左右但 **takerate（净收入率）才是真实变现率**。处理：净收入 = gross 收入 × takerate，再按净收入给平台倍数（汇量 gross PS 8.9x → 净额口径真实 PS ≈ 2.3x，结论完全不同）。**与流量代销的区别**：流量代销（迈富时 5%）无技术含量直接剔除；程序化广告（汇量 takerate 25.56% 且提升中）有算法/数据壁垒，用净额法重估。看到毛利 15-25% 的大额收入段先问「gross 还是 net」。

### 「数据飞轮」闭环定义
客户使用 → 数据沉淀 → 模型/产品变强 → 更多客户 → 更多数据。**闭环必须可验证**（有证据链：如「客户数据进训练→benchmark 提升→新客户因能力增强而来」）。只是「有数据积累」不算飞轮。

### 「高切换成本」三来源
数据锁定（客户数据在你平台，迁走即失）/ 流程嵌入（业务流已改造）/ 合同锁定（长期合同+违约成本）。**至少满足两项**才算高切换成本。

## §2 「纯验收 vs 有沉淀」定性判据（v1.8.5 定位更新——估值分档合并，判据转为定性分析用）

**背景**：v1.8.5 起第零档**不再分估值子带**（有沉淀/纯验收单太抽象，估值倍数统一按项目制硬锚 0.5-3.5x）。本判据转为**定性分析**（报告维度三/质量分的数据回流、归因资产化打分依据）。四信号：

| 判据 | 项目制信号 | 有沉淀信号 | 数据可得性 |
|---|---|---|---|
| 重复收入占比 | 一次性项目 >80% | 订阅/用量/结果 >30% 且上升 | ✅ 招股书/年报分部 |
| 复购/续约率 | <30%（做完就走） | >50%（客户加购/续签） | ✅ 招股书有（滴普 33.2% 复购 vs 留存 14.6%） |
| 交付物复用 | 每个项目从零做 | 同一组件被 N 个项目复用 | ⚠️ 需 IR 问 |
| 研发资产化 | 研发全费用化 | 有产品组件沉淀（ModelHub/图数据库/算法库） | ✅ 招股书技术章节 |

**判据组合**：重复收入占比 >30% **或** 复购率 >50% **或** 有明确产品资产 → 有沉淀；否则项目制。

**实证**：范式 1.87x（有沉淀：在手订单 89 亿 + ModelHub 3 万模型）vs 中软 0.5x（纯人力：无产品资产）——判据能把它们分开。

## §3 按用量（token/API）业务定价规则（v1.7 新增，v1.7.3 应用层转售锚重校）

**背景**：按用量收费（token/API/调用）的公司定价逻辑和订阅完全不同，且 gross/net 坑最大。规则：

1. **先问 gross 还是 net**——毛利 15-25% 大额收入段用净额法重估（汇量教训）；纯 API 路由（OpenRouter 类）take rate 5.5% 必须用净收入，gross GMV 巨大但 PS 无意义
2. **转售的 PS 跟增速+生态/自研挂钩，不是固定带（v1.7.3 主人校准 + 2026-08-31 修正）**：
   - **Liblib 实证**：增速 +3000%（2026-05 同比）却只给 6.7x——锁死它的不是毛利，是**单点功能风险**（无自研模型、聚合第三方、可被模型厂原生覆盖；36氪「模型未收敛时的阶段性产物」）。Suno 同 ARR 3 亿给 18x——差距在 Suno 有自研模型
   - **OpenRouter**：毛利 70%（路由抽成）→ $7.5B Stripe 收购 ÷ $140M ARR = **53.6x**（战略收购溢价标 ⚠️；高毛利+超高增速 28 倍）
   - **Cursor 早期**：**毛利为负**（API 成本 ≈100% 收入）却拿 54-100x——靠 IDE 入口+开发者生态+自研模型预期；后自研 Composer 转正
   - **核心修正（2026-08-31）**：转售倍数**不是被毛利锁死**——毛利负的 Cursor 54-100x、毛利健康（订阅+积分）的 Liblib 6.7x。真正的分水岭是**有没有自研/生态/入口**（可替代性）+ 增速。毛利只影响单位经济可持续性，不影响当期倍数
3. **用量型毛利随规模改善**——看单位成本趋势不是静态毛利（范式 API 折旧 +290% vs 收入 +860% 剪刀差）
4. **模型层 API（OpenAI/Anthropic 类）单列不入应用矩阵**——估值逻辑是战略期权
5. **推理平台（Baseten/Together/Fal）不参与应用层锚点（v1.7.3 主人裁决）**——它们卖算力/推理基础设施，是基础设施层不是「转售智能」应用层；锚点只取应用层转售（Liblib/OpenRouter/Cursor 早期）

| 按用量类型 | 锚点 | PS | 档位 | 口径注意 |
|---|---|---|---|---|
| 纯转售·无自研无入口（g1-g3） | Writesonic ~5-8x / Copy.ai ~12x⚠️ | 3-8x | 二档·纯转售（tier2a） | 单点功能风险锁死 |
| 纯转售·无自研无入口（g4 >60%） | **Liblib 6.7x（+3000% 仍锁死——增速期权≈0）** | 4-8x | 二档·纯转售（tier2a） | 增速 3000% 也只值 6.7x——纯转售增速溢价不存在（v1.7.13 主人校准：Liblib 增速属 g4 非 g1） |
| 转售+入口/生态（有产品层/入口，模型转售） | Cursor **15x total**（收购价含战略溢价，v1.8.7 修正）/ ElevenLabs 22x / Suno 18x / Replit 17.1x / Lovable 26.6x | 15-35x（2026-09-01 merge：原 2c 并入自研型，早期数据全拿掉） | **三档·自研智能（tier3，v1.9.0 merge 原 tier2s+tier3——自研 vs 收智慧租不硬分档，档内双判据插值）** | 入口强度决定倍数：IDE>路由网络>产品编排>平台；OpenRouter 战略溢价 ⚠️；Cursor 收购价含溢价（§8） |
| 自研型·按量（自研模型+API） | ElevenLabs 22-35x / Suno 18x | 15-35x | 二档·自研型（tier2b） | 自研是定价核心 |
| 自研型·按量（编码） | Cursor 15x total / 23x B2B（当前）/ 29x forward | 15-35x | 二档·自研型（tier2b） | 双口径必标 |
| 模型层 API | OpenAI ~35x / **Anthropic 21-31x（2026-08 更新）/ Mistral 57x（在谈）** | 战略期权 | 单列不入应用矩阵；**期权需三档迁移证据（§12）** | — |

**三档 g3/g4 边界（v1.14.0 审计加注）**：g3 上沿 ≈ g4 下沿——Glean 24x(+89%) 增速属 g4 但倍数落 g3 上沿；质量 7-8 中带公司跨档参考（增速 60%+ 但质量 7 给 25-30x = g3 上沿 + 少量；只有质量 ≥8 才进 40-50x）。增速 g4 + 质量 <7 = 自研无飞轮（Cursor 15x 档）——**不是所有 g4 增速都配得上三档上沿**

**转售倍数判定（v1.7.13 三分层）**：先分「有无入口/生态」→ 无（纯转售，Liblib 型）3-8x 增速期权≈0；有（转售+入口，Cursor 早期/Lovable/Replit 型）17-55x 看入口强度；有自研模型（Cursor 现在/ElevenLabs/Suno）15-35x。**增速只在「有入口/自研」时给弹性——纯转售里增速期权≈0**（Liblib +3000% = 6.7x vs Lovable +150% = 26.6x，差的是入口不是增速）。范式 API 段毛利未披露（整体 32.8%）——若 API 段毛利 30-40% → 接近 Liblib 带；若 Token 工厂自研调度能到 50%+ → 中间态带（10-30x）。

## §4 五死因语义

1. **概念热（需求真伪）**：需求是否在真实业务场景中被验证为付费需求？（有客户真金白银买单 = 真实；只有概念热度/演示/咨询 = 虚火）
2. **无存量预算（预算来源）**：客户原本就有为这件事花钱的预算科目吗？（替换预算 = 有存量；新创预算 = 慢死——企业不为「从来没花过钱的事」立项）
   > **与死因 1 的区分**：概念热 = 需求真伪（价值验证）；无存量预算 = 预算来源（付费习惯验证）。无预算但需求真 = 慢死（要教育市场）；有预算但伪需求 = 快死（客户不续费）。
3. **单点功能**：own vs rent——见 §5 精确定义
4. **价格战三型区分**：
   - 行业性红海（全行业毛利普遍下滑、玩家同质化）→ 🔴 致命
   - 主动降价获客（毛利短期降但单位经济改善、客户 LTV 上升）→ 🟡 观察
   - 毛利下滑但产品/客户结构变化（范式智能 34.8% 是产品组合变化，**不是价格战**）→ ✅ 先归因再判定，禁止直接判价格战
5. **责任链两要件**：可归责（公司有明确责任承担机制/合同条款/保险）+ 可补救（错误可检测、可修正、影响可隔离）。两要件缺一 = 断裂 = 卖不动（医疗/法律/金融高危；消费级陪伴类低危）

**量化检查项**：客户留存率 <30% = 单点功能的量化证据（滴普 14.6% 实证）——价值无沉淀 + 零切换，客户用完就走。注意：项目制客户本来可能一次性交付，留存率低不必然致命，须结合「有没有重复付费业务」判断。

## §5 单点功能精确定义（2026-08-27 主人纠正后定稿）

**单点功能风险 = 价值是否集中在「可被模型原生能力免费/廉价覆盖的那一层」**。判断三个条件，**必须同时满足才算致命**：

| 条件 | 问题 | 反例（不构成风险） |
|---|---|---|
| ① 价值层级 | 价值全在「调模型」这一层，模型之上无沉淀 | 沉淀了领域数据/know-how/客户关系/合规资产 |
| ② 替换成本 | 用户换成模型厂原生功能是零成本 | 数据已沉淀、流程已嵌入、团队已培训（高切换成本） |
| ③ 底座形态 | **闭源 API 深度依赖**（可被改价/收回/加原生功能） | **开源底座**——不会被收回，升级反而增强你的地基 |

**核心红线：开源基座 ≠ 单点功能风险。** 开源模型（DeepSeek/Qwen 类）不会被模型厂收回，模型升级只会让底座更强、不会让上层 know-how 失效。真正触发风险的是「闭源 API 深度依赖 + 价值无沉淀 + 零切换成本」三者齐备。

**判定速查**：
- 套壳翻译/通用问答工具 → 🔴 高风险（纯薄包装 + 原生更好 + 零切换）
- 基于开源模型做银行反欺诈 → ✅ 低风险（原生没有银行数据/合规流程，替换成本高）
- 基于开源模型做企业知识库 → ⚠️ 看沉淀：风险在「领域数据集够不够厚、能否形成数据飞轮」，不在「基座是开源的」
- 闭源 API 依赖的纯转售/路由 → 🔴 高风险（上游可改价/收回/加原生功能）

## §6 质量七指标口径（0-10 打分，与账本三核查正交——v1.15.0 MECE 整合）

> **MECE 分工（v1.15.0 整合，消除原「六指标 vs 七指标」4/7 重复）**：
> - **账本三核查**（报告第五章上表，纯财务视角，用判断刻度不用 0-10 分）：①IER ②训练/推理配比 ③现金流质量——回答「钱有没有在资产化」
> - **质量七指标**（本表，0-10 分）：智慧自有率/单位结果成本/数据回流/归因资产化/护城河层数/爬升检验/毛利结构——回答「资产化得好不好」
> - 原「财务核查六指标」的 IER 留在核查表；智慧自有率/数据回流/归因资产化归本表评分；单位成本趋势并入毛利结构指标（成本视角见核查 IER 趋势）

| 指标 | 定义（口径写死） | 高分信号 | 低分信号 |
|---|---|---|---|
| 智慧自有率 | 客户实际使用路径中，**后训练级以上**自有模型完成的推理量占比（不含纯调用） | 六成以上 | 三成以下 |
| 单位结果成本趋势 | 先定义**结果单元**（每成功解决/每单/每次转化，按公司业务定），再算该单元成本环比 | 持续下降 | 持平/上升 |
| 数据回流 | **产品设计回流**（产品是否设计成「客户数据→训练→服务增强」闭环；非合规强制，是产品设计） | 设计成回流闭环 | 用完即走 |
| 归因资产化 | 三子项：①**独有 eval 基准**（客户带不走的评估资产）②**独占数据**（合法且不可复制的训练数据）③**可导出权重**（自有权重可部署/授权） | 三者至少二 | 全无 |
| 护城河层数 | X 系列六层：**品牌/数据/规模/网络效应/切换成本/独占资源**——长到第几层 | 4 层+ | 停在 1-2 层 |
| 毛利结构 | 毛利率+毛利额趋势（软件级 70%+ / 服务级 40-55% / 转售 <40%）——回答「收租还是搬砖」 | 软件级且毛利额在涨 | 转售级或毛利额萎缩 |
| 爬升检验 | 收入结构真向高档迁移（项目→订阅→用量→结果），占比证据说话 | 有页码级证据 | 自称但占比 <15%（嘴爬） |

> 护城河六层定义（对齐 X2《套壳不是终点》）：品牌 = 客户指名购买；数据 = 独有数据资产；规模 = 单位成本随量下降；网络效应 = 用户越多产品越值钱；切换成本 = 客户迁移代价；独占资源 = 牌照/算力/渠道等不可复制资源。


### 打分语义锚定表（v1.8.2，质量分 0-10 怎么给——避免拍脑袋）

| 指标 | 高分（8-10） | 中分（5-7） | 低分（0-4） |
|-------|------|------|------|
| 智慧自有率 | 自研/后训练模型承担推理六成+ | 有自研层但占比中等 | 开源基座微调/纯租 |
| 单位结果成本趋势 | 结果单元成本持续下降 | 持平 | 上升/未披露 |
| 数据回流 | 产品设计成「数据→训练→增强」闭环 | 有回流但非强制 | 用完即走 |
| 归因资产化 | eval+独占数据+可导出权重 ≥2 项 | 有 1 项 | 全无 |
| 护城河层数 | 4 层以上 | 2-3 层 | 1 层或无 |
| 毛利结构 | 软件级 70%+ 且毛利额涨 | 服务级 40-55% 持平 | 转售级 <40% 或萎缩 |
| 爬升检验 | 收入结构真向高档迁移（有证据） | 方向对、斜率未证实 | 嘴爬（BP 写了不动） |

### 收入单位实证纪律（v1.8.2，滴普教训——定档第一铁证）

**必须读年报/中报「收入确认」附注，不能凭「SaaS 公司」「AI 应用第一股」标签猜**：
- **时点法（于某一时间点确认）= 项目交付/验收制** → 第零档铁证
- **期间法（于某时间段确认）= 订阅/按量** → 一档/二档铁证
- 比例口径：滴普时点法 99.2% = 项目制实锤（2026 中报）；期间法占比越高，档位越高
- 辅助线索：合同负债（订阅预收）、贸易应收天数（回款慢=项目制）、单客户收入结构

### 口径纪律（v1.8.2，留存率/获客成本防误读）

- **留存率先问口径**：客户数留存 ≠ NDR（净收入留存）。项目制公司客户数留存低是常态（滴普 1H25 14.6%），那是「老客户还剩几个」，不是「收入端留住了多少」——写报告必须标口径+时点+计算方式
- **获客成本先问算法**：「销售费用÷新增客户数」≠ 标准 CAC（销售+市场费用/新签客户）。国证国际口径 = 当期销售费用÷新增客户数（滴普 115 万/新客）——比标准 CAC 偏高
### 信息时间衰减纪律（v1.8.3，主人 2026-09-01 要求「数据来源新规则按信息时间衰减」）

**信息有半衰期——数据点的可靠性随时间衰减，写报告必须标注信息时点并按衰减程度降级使用：**

| 数据类型 | 衰减阈值 | 处理 |
|---|---|---|
| 财务数据（收入/毛利/留存率等） | 距最新报告期 >1 个报告期 | 标「历史口径，需更新」，**不作定档/估值主判据**，只作背景或交叉参考（滴普教训：1H25 招股书留存率 14.6% 在中报已出后仍被引用，属衰减数据） |
| 行情/估值数据（市值/PS/PE） | >7 天 | 标「时点数据，发布前重核」——发布前当天重核（埃森哲/Salesforce PS 2026-08-27→08-31 四天变 25%，Salesforce 3.83x→4.80x） |
| 媒体/研报 | >3 个月 | 只作背景，不作关键数据主源；关键数据必须从最新年报/中报取证 |

**来源索引表必须带「信息时点」列**（| [N] | 来源 | 类型 | 等级 | 信息时点 | 链接 |），每个来源标注数据采集日/报告期；衰减数据在时点列显式标「（已衰减）」。

## §7 X 系列哲学详版（v1.4 合并去重版）

### 披露充分性评估（Step 0.5）
**目的**：X 系列深度判据（推理成本占比/数据飞轮闭环/NDR 拆解）在上市公司披露中大多拿不到——先评估「能拿到什么」，避免瞎编。

| 披露等级 | 判定 | 处理 |
|---|---|---|
| ✅ 披露充分 | 招股书+年报+分部数据全 | 正常四步 |
| ⚠️ 披露部分 | 有年报无分部/关键科目缺失 | 走四步但标注推断 |
| ❌ 披露不足 | 刚上市/数据少 | **降级输出**：只给定档+生死关，不给估值或给宽区间 |

**上市公司披露可得性速查（2026-08 实测）**：
| X 判据 | 披露可得性 | 说明 |
|---|---|---|
| 收入单位（seat/token/outcome） | ⚠️ 部分 | 年报分部能看出收费模式，不按单位拆——自己判断 |
| 推理成本占收入 | ❌ 不可得 | 港股只有「销售成本」，不拆推理成本 |
| 模型降价毛利影响 | ❌ 不可得 | 纯推演 |
| 护城河六层细节 | ⚠️ 部分 | 招股书技术章节有；「写回客户系统/数据回流闭环」几乎没有 |
| NDR 拆解 | ❌ 不可得 | 港股 SaaS 连 NDR 都少披露，拆解不可能 |
| 结果定价占比 | ✅ 可得 | 收入模式披露会写 |

### 三态标注铁律（防 AI 脑补）
1. 每个判断标「✅披露可证 / ⚠️推断 / ❌缺失」
2. ❌ 维度**禁止给具体数字**，只能写「未披露，需 DD/调研」
3. ⚠️ 推断必须带依据（如从毛利结构推断推理成本区间），不能凭空给数
4. validate 检查：❌ 标注维度出现具体数字 = 硬错

### 三问定档法（X1，比读 BP 护城河章节更快——答案在利润表里）
1. **你的收入单位是什么？**（seat/token/成功次数——披露可得 ✅）答案直接告诉你它在哪一档
2. **推理成本占收入多少、趋势在降吗？**（披露不可得 ❌ → 从毛利结构推断 ⚠️）趋势在降说明积累自有智能资产；升或持平就是纯搬运
3. **如果明天底层模型大幅降价，你的毛利会怎样？**（披露不可得 ❌ → 推演 ⚠️）扩张=智慧租（三档）/ 收缩=转售商（二档）/ 没影响=功能租（一档）

### 付费单位「混合态」（v1.7.6 金蝶灵基校准——主人问「AI 原生还是订阅吗」）

**背景**：X1 三问的 seat/token/outcome 是理想三档，现实中公司常是**混合付费**。金蝶灵基官方定价 =「席位数 + 灵基点数」（点数 = AI 调用/智能体运行消耗，本质是 token 包装，同 SAP AI Units）；管理层明示「基于调用量的收费占比持续提升」。

**规则**：
- **seat+token 混合 = 爬升的中间态**（纯 seat → seat+token → outcome），不是新档位
- 判断标准：**用量部分占比是否上升**（管理层原话/分部收入趋势）——上升 = 真爬（金蝶灵基 8/10），纹丝不动 = 嘴爬
- **不自研模型的公司只能给「档内用量溢价」，不能跳档**（金蝶整体一档 g1，token 增量进质量分爬升检验，不单独拆段）；Cursor 式 seat+token 能跳二档是因为有自研 Composer
- 披露可得性：定价模式（官网/发布会 ✅）；用量收入占比（分部 ⚠️ 需拆）
- **套用问题**：「有没有按结果付费？」——多数 AI 原生 SaaS 没有（金蝶无 RaaS）；有 RaaS 且增速兑现才谈三档

### 爬升检验（第七指标·动态，X2 哲学）
静态定档之外，判断「加厚 vs 停滞」——**收入结构是否在向高档迁移**（从 token 按量 → 按结果收钱，高毛利/按结果收入占比是否上升）。
- ✅ 真爬：能力逐层答得上（六层加厚有证据）+ 收入结构往高档走（按结果收入占比在升）
- ❌ 嘴爬：BP 写满垂直深耕，收入结构十年不动（token 占比纹丝不动）
- **披露可得性**：分部收入结构变化（年报 ✅）；按结果付费占比趋势（年报分部可推断 ⚠️）
- 与六指标关系：六指标是静态快照（现在值多少分），爬升检验是动态斜率（往哪走）——两者都填才完整

### NDR 拆解纪律（X4 哲学）
AI 公司 NDR 会被用量虚增——客户多跑任务，账单涨、推理成本也涨，产品没变好。NDR 涨先问哪部分涨：
- 客户数留存涨 = 真好
- 单客户用量涨 = 看毛利扛不扛得住（他多用的 token，你的毛利扛不扛得住）
- **披露不可得 → 写「未披露，需 IR/调研」，不编数**

### 壳层≠必死修正（X2 哲学）
死掉的从来不是「套壳」，是「停在第一层」的公司——套壳是 AI 应用的起点不是终点。判断生死看是否在**加厚**（工程运行时/工作流嵌入/数据飞轮/分发渠道/结果定价，每加厚一层模型升级就伤不到你），不是看它今天是不是壳。
- 披露可得部分：研发投入/技术章节 ✅
- 判断问句：这家公司在加厚吗？（答得出具体加厚证据 = 活着；答不出 = 停在壳层）

### 闭源 SOTA 判据（X2，定档不适用边界的完整判据）
**「这个领域的模型能力，开源模型 + 垂直数据能不能追平闭源 SOTA？」** 能 → 应用层有私有化智慧空间，值得一步步加厚；不能 → 套壳就是终点（问题只是认不认）。
- 能追平：客服（Fin Apex）、图像（Liblib Star-3）——开源可达，延伸得动
- 追不平：视频（Seedance/可灵）、编码（Claude Code 亲自下场）——应用层自研追不上，Lovable/Replit/TapNow 停留在路由和分发

### 护城河加厚路径六层（X2，判断生死/定档的深层依据）
基座模型（可替换？）→ 工程运行时（自研 agent loop？）→ 工作流嵌入（写回 System of Records？）→ 垂直数据飞轮（越用越强？）→ 分发渠道（自有接口 or 寄生？）→ 结果定价（按结果收钱？）。每加厚一层，底层模型升级就伤不到你；**停在壳层的公司，基座一升级就死——死掉的从来不是「套壳」，是「停在第一层」的公司。**

## §8 锚点纪律：次新股不可作估值锚（v1.6.1 主人硬性要求）

**次新股（上市 <12 个月或老股东未充分解禁）的市场估值含「流通盘稀缺溢价」，不是基本面均衡价——禁止作为估值锚点参考，只能作反例/偏离参考。**

- **可用锚点**：①充分解禁的老股（上市 >12 个月且老股东已解禁，如范式智能 2023-09 上市、金蝶/中软等老牌）②一级市场非上市标的（Harvey/ElevenLabs/Liblib 等，无流通盘问题）
- **不可用锚点**：次新股（极视角/海致/滴普/群核/迅策/聚水潭/科拓 2025-2026 上市）——其市场 PS（25-35x）是低流通盘 + 叙事推高的，不是该档位的合理倍数
- **反例锚 vs 估值锚区分**：次新股可作为「偏离分析」的反例锚（说明市场如何被扭曲），但**绝不能出现在附录 B 锚点明细表的「可参考倍数」栏**；锚点明细只列充分解禁标的
- 一级市场锚点同样检查：若一轮融资刚发生且未验证持续（如 Legora 单源），标「单源待验证」不参与主带

### 收购价 ≠ 公允倍数（v1.8.7 主人质询「cursor被收购是不是估值倍数不对」——战略收购溢价纪律）

**战略收购价（含控制权溢价）≠ 公允市场倍数**——收购方为数据/人才/生态付的溢价，不是少数股权融资的公允价。用收购价直接当锚会虚高：

| 案例 | 收购价 | 独立估值 | 处理 |
|---|---|---|---|
| Cursor | $60B（SpaceX 全股票收购 2026-06，动机=数据喂 Grok+人才）÷ $4B ARR = **15x** | Series D $29.3B（2025-11）÷ 最新 ARR ≈ 7-15x | 主锚用 15x total 并标注「收购价含战略溢价」；23x B2B 仅辅助；市占 41%→26% 减速期收购价更不反映公允倍数 |
| OpenRouter | $7.5B（Stripe 收购 2026-08）÷ $140M = **53.6x** ⚠️ | — | 只作上沿参考/偏离活例，不参与主带 |

**规则**：①锚点标注「融资价」vs「收购价」——融资价是公允市场价，收购价需标注含溢价 ②被战略收购的公司若市占在减速，收购价更不能代表公允价值 ③收购价可作为「上沿参考/偏离活例」，但不作为档位主锚 ④一级市场锚优先取最近一轮**融资**估值（少数股权，公允），不是并购估值。

**次新股系统性检验（v1.7.13 主人要求「拉次新股看看哪些在区间外/内」——2026-08-31 实证，纪律最强验证）**：
- **区间外（高 2-6 倍）的全是低流通盘（发行 <10%）**：明略 12.7x（发行 5%）/ 极视角 17-35x（自由流通 10%）/ 海致 13-23x（5.9%）/ 滴普 8-13x（无基石）——远超一档 g4 港股锚带（4-6x）
- **区间内的全是流通充分（发行 >10%）**：群核 4-6x（一档 g3 带内）/ 科拓 4-5x——落带
- **结论**：低流通盘稀缺溢价是次新股偏离的唯一系统性来源；检验公式 = 次新股按「流通盘比例」预判落带与否（<10% → 大概率带外，只作反例；>10% → 可参考）
- **验证意义**：不是「次新股都贵」——是「低流通盘次新股都贵」；流通充分的次新股定价与老股锚带一致，说明矩阵本身有效


## §9 算力/Infra 段（SOTP 专用分类，v1.7.4 主人校准——范式 API = 无问芯穹型）

**背景**：范式智能 API 段深挖发现——自持/纳管算力 + Token 按量交付 + 异构调度技术的业务，**不是「应用层转售」**（Liblib/OpenRouter/Cursor 锚不适用），而是**算力基础设施段**（类似无问芯穹/Nebius/CoreWeave）。SOTP 拆分时此类业务**单列一段，不入应用层矩阵**（类似模型层单列）。

**判据**（全部满足才算算力段）：
1. 自持或纳管算力资产（GPU 集群/PFLOPS），资本开支大（范式 22.37 亿/半年）
2. 收入按 Token/算力用量计费（不是订阅/项目）
3. 有异构调度/推理优化技术（HAMi/FlashDecoding++ 级：利用率提升、单位成本下降）
4. 定价靠「技术优化溢价」（同等算力产出更多 Token），不是硬件倒卖差价

**重/轻资产判断检查项（v1.7.7 主人质询「API 是重资产还是轻资产」——范式实证）**：
- **不能看折旧当期值**：资本开支刚转固时折旧滞后——范式 1H26 折旧仅 2486 万 vs PP&E 16.62 亿（GPU 期内新买，H2 折旧 ~1.6 亿/半年才显现）。低折旧 ≠ 轻资产
- **看 PP&E vs 使用权资产/租赁负债比例**：PP&E 远大于使用权资产+租赁负债 = 自购自持（重资产）；反之靠经营租赁 = 轻资产。范式实证：PP&E 16.62 亿（半年 +471%）vs 使用权资产 1.74 亿 / 租赁负债 1.09 亿 → **自购自持为主**（借款 16.6 亿买算力）
- **云服务费 ≠ 算力租赁**：大额外采技术服务费可能含 AI Platform 交付外采 + 弹性峰值补充（范式 9.83 亿），不能直接解读为「算力全是租的」
- **重资产 H2 折旧压力**：毛利率前瞻要叠加转固折旧（范式 1H26 32.8% 已降 4.95pp，H2 再叠 ~1.6 亿/半年）——重资产段倍数偏下沿的原因之一

| CoreWeave（纯 GPU 租赁） | 10.3x | 重资产高杠杆、毛利 ~59% |

**使用规则**：算力段倍数**先按资产轻重分档（v1.7.5 主人校准）**，**区间按国内实际情况校准（v1.7.7 主人质询）**：
- **重资产自持**（自建/自购 GPU，折旧吃利润）：**5-10x（国内校准版）**——国内有效区间 4.45-10.67x（青云 10.67x 失真剔除 → 有效 4.5-10x），**中位 ~7.5x**（优刻得 7.57x / 首都在线 7.69x / 并行 4.45x）；下沿 5x（并行 4.45x 含北交所折价，取整）；上沿 10x（高增速+低杠杆，范式 20 倍指引）；**CoreWeave 10.3x 只是海外上限参考，国内普遍给不到**；高杠杆折价、低杠杆可略抬
- **轻资产纳管/调度**（运营别人的算力，无折旧）：软件属性 → **15-25x**（可参考 Nebius 软件厚度溢价 / 无问芯穹一级）——⚠️ 无国内上市样本，推断格
- 按毛利微调：<40% 偏下沿 / 40-60% 中带 / >60% 偏上沿
- **国内竞争烈度折价**：国内 Token 服务竞争激烈（阿里/字节/无问芯穹/优刻得/硅基流动）→ 范式 API 6-10x（国内中位 7.5x 为锚，增速溢价上探）
- 一级市场无问芯穹型可参考累计融资/收入比

**与模型层的区别**：模型层卖「模型能力」（训练/推理自己的模型）；算力段卖「算力+调度服务」（跑别人的模型/自己的调度栈）。模型层单列不入矩阵（战略期权）；算力段同样单列（重资产+公用事业化定价），但可以用 Nebius/CoreWeave 公开锚。

## §10 中国 vs 海外倍数折价（v1.7.9 迈富时案例——最重要的框架校准）

**背景**：迈富时 AI 应用段（毛利 76.6%、增速 +123.7%、ARPU +80%、现金流转正）按一档 g4 理论 30-50x 估值 → 1,221-1,526 亿，比市场高 8-10 倍——**中国高增速 SaaS 没有 CrowdStrike 式定价**。这是框架最大的中国化缺口。

### 一档 g4 校准（v1.7.10 主人纠正——30-50x 无实证，废弃）
- **海外实证批判**：原「CrowdStrike 41x = g4 唯一实证」**不成立**——CrowdStrike 2026 增速实际 **25.7%**（g2 上沿，非 g4）；2026-08 实测海外高 PS SaaS：Cloudflare 42.5x（增速 34.7%）/ CrowdStrike 41.4x（25.7%）/ Snowflake 22.6x（33.5%）/ Datadog 21.5x（34.0%）——**增速只有 20-35%，公开市场无「增速 >60% + 高 PS」订阅 SaaS 样本**
- **一级市场锚剔除**：Harvey 44-52x / Perplexity 40-51x **非订阅制**（主人纠正）——不入一档订阅锚
- **中国实证**：市场给迈富时 AI 段隐含 **4.88x**（148.8 亿 ÷ 30.5 亿 2026E）、中国高增速 SaaS 最高 7-8x（石基 7.67x / 卫宁 6.88x）
- **校准后规则**：
  - 一档 g4 **海外（>60%）**：**15-25x**（g3 上沿外推，⚠️ 仍推断——当前最高速公开样本 35% 增速给 42x，>60% 无实证不能再高）
  - 一档 g4 **中国（>60%）**：**4-6x（港股锚带 g4，v1.7.12 实测：金蝶 3.55/金山 2.98/涂鸦 3.38/美图 4.44/阜博 2.47/联易融 3.81/迈富时 4.88）**——替代旧 4.5-8x 倒算值（v1.7.10 废弃 30-50x 后统一：中国一档 g4 直接用港股锚带，不再倒算）
  - 增速 >100% 爆发期（低基数+KA 集中）再 ×0.7 折扣
  - **倒算方法（v1.7.11 主人要求）**：高增速公司定档前先倒算市场隐含 PS——市值 ÷ 各口径收入（2026E/TTM/2025），多口径交叉看市场真实定价；迈富时实证：forward 4.88x / TTM 7.05x / 2025 10.01x——**增速越快 forward 倍数摊薄越狠，倒算必须用 forward 口径**
- **适用边界**：仅一档 g4（>60% 增速）——g1/g2 已被国内锚带覆盖（见下），不重复打折
- **为什么**：中国高增速 SaaS 面临国内竞争（阿里/字节/腾讯生态）+ 付费意愿 + 增速持续性存疑（低基数+KA 集中），市场不给海外式「增速期权」定价

### 中国市场「增速期权缺失」底层机制（v1.7.13 主人质询「原因是什么？是不可持续吗」——比「竞争激烈」更准确的解释）

**不是（或不只是）增速不可持续——是三个层次的「信任赤字」叠加，导致中国市场的定价变量是确定性（盈利/现金流/粘性），增速是折扣项不是溢价项：**

| 层次 | 中国（迈富时 4.88x，+100%） | 海外（CrowdStrike 41x，+25.7%） |
|---|---|---|
| 品类刚需度 | 营销——预算可砍（非刚需） | 安全——不能停（刚需） |
| 客户粘性 | KA 集中（69.1%）、竞争激烈 | 长合同、全球龙头 |
| 兑现记录 | 上市 27 个月、无长兑现史 | 10 年持续兑现 |
| 市场环境 | 港股小盘（流动性折价） | 美股（流动性溢价） |
| 创伤记忆 | 微盟 -90% / 有赞 -95% / 商汤 / 云从——「高增速叙事→证伪→崩塌」被反复教育 | 无同等系统性创伤 |

**操作含义**：
- **中国市场给的是「已兑现业绩」的定价，不是「未来增速期权」的定价**——迈富时 ≈ 利润 PE 定价（2.03 亿净利 × ~36x ≈ 市值），增速 100% 在定价里几乎不加分
- 市场在说：「你先证明 2027 年还能 +70%，我再给你增速的钱」
- **增速是折扣项不是溢价项**——因为中国高增速大多被证伪（创伤记忆），市场学乖了
- 对中国高增速 AI 应用公司：**不写「增速快所以高倍数」，写「确定性/现金流/利润先证明，增速只作确认」**

## §11 框架边界（v1.7.12 主人纠正——汇量案例：类别错误排除）

**背景**：汇量科技（Mintegral 程序化广告）被误放进 AI 应用框架（按「二档·纯转售」估）——主人纠正：**它是广告交易平台（双边市场撮合，赚 take rate），不是 SaaS 也不是 AI 应用**。已从港股一档锚带表移除。

**排除规则**（以下类型不入 AI 应用框架，用各自的估值逻辑）：
- **交易平台**（广告/电商/支付/打车撮合）：赚 take rate/GMV 抽成——用平台估值（AppLovin / The Trade Desk / 美团锚），不是档位×增速矩阵
- **纯硬件/芯片**：用 PE/PS + 周期逻辑
- **人力外包**（中软国际/汉得型，人天卖人头）：**不入框架**（主人 2026-08-31 裁决——纯人力外包脱离 AI 应用档位；第零档·项目制只保留给有 AI 技术含量的项目制公司，如范式智能 AI Platform 段）
- **硬件转售/算力贸易**（中软 AI 全栈构成——服务器贸易）：不入框架（毛利极低过路收入）
- **模型层**（OpenAI/Anthropic 型）：战略期权单列

**判据**：收入单位是不是「撮合交易抽成」——是 → 交易平台，不入框架；收入单位是「软件功能/智能转售/算力服务」→ 入框架。**毛利 15-25% 的大额收入段先问 gross/net，再问是不是交易平台**（汇量教训：Ad-tech 是平台不是转售智能）。

**AI 驱动资产运营商（v1.7.14 美克生案例——第四类框架外）**：
- **定义**：AI 是内部运营工具（提高自有资产的收益率/效率），**不是产品收入**——收入单位是资产开发/资产买卖/服务费，不是 seat/token/outcome
- **美克生能源（Makesense Energy，2026-04 递表港交所）实证**：中国最大分布式储能资产运营商（799.5MWh，7.4% 份额第一）。收入 5.20 亿（2025，+317%）中 **89% 是储能资产开发**（开发-建设-转售，一次性项目收入，招股书原文「本质上是一次性的」）+ 9.5% 电力服务；毛利率 2.6%→4.2%→10.0% 极低；研发占比 34%→**3.7%**（AI 是标签不是投入）；前五大客户 84.3%；累计亏损 10.62 亿、资产负债率 193%
- **「蘑菇小美」AI 智能体**（电价预测/充放电调度优化/交易策略）：2026-01 上线、**零收入**——是赋能工具不是产品。技术真实（PSS 电化学模型硬件求解器 + 绿电来平台云边协同 + 蘑菇小美决策层，物理 AI 早期原型），但 AI 价值体现在「资产收益率」而非「AI 收入」
- **赋能型 AI vs 产品型 AI 判据**：①AI 能力是否对外出售（产品）还是只内部使用（工具）②AI 是否单独披露收入（有 = 产品；无 = 工具）③收入单位是否含 token/结果（无 = 不是 AI 应用）——**赋能型 AI 不给 AI 应用倍数，资产/服务按资产运营商逻辑估（NAV/PE/装机量）**
- **对标**：Tesla Autobidder（2023 为用户创造 3.3 亿美元交易利润但不直接收费，是 Megapack 的卖点——软件是硬件的推手不是独立收入）；国能日新（301162.SZ，见 §13）是「卖 AI 服务」的产品型对照
- **期权纪律**：蘑菇小美产品化（开放平台+交易分成）= 三档收智慧租期权——但需政策放开+平台落地，当前零收入，**不给估值**（商汤模型层期权同纪律 §12）
- **识别信号**：收入高增速但来自「资产开发/硬件/工程」而非软件；毛利 <11%；研发占比骤降；AI 只在战略叙事里不在分部收入里


**中软国际案例（v1.7.12 主人裁决——剔除）**：「AI 全栈 15.32 亿（+133.7%）」经拆解 = 算力硬件转售（服务器贸易「贡献当期利润」）+ 智算中心项目（10 亿）+ FDE 人天交付 + 模型适配——**AI 外包/项目制/硬件转售混合，非 AI 产品收入**。公司主体为纯人力外包（IT 服务 85%+）。判定：**不属 AI 应用框架，剔除**。纪律：**「AI 收入高增速」≠「AI 产品收入」——必须先拆构成**（算力转售/项目交付/人天服务 → 框架外或第零档；产品订阅/Token 分成 → 才入框架）。


## §12 模型层期权纪律（v1.7.12 主人裁决——商汤案例）

**背景**：商汤 U1 自研基座（NEO-Unify 架构）被考虑给「模型层期权」估值——主人裁决：**开源小模型不入流，无三档迁移证据不给估值**。

**规则**：
- **模型层期权 ≠ 有自研模型就给倍数**——需要「能实现三档（收智慧租/outcome）高档位迁移」的证据
- 证据清单（至少一项，且可验证）：①outcome/结果定价收入已产生 ②付费客户高增长 + 模型竞争力（国际基准/开源影响力）③智能体按结果计费落地
- 商汤案例：U1 开源 8B 小模型（星标 1.1 万 vs DeepSeek 数十万）——「Token 结果计价」是规划未兑现——**期权 = 0**
- **开源影响力弱的小模型（星标 <5 万 / 参数 <50B）不给模型层期权**——对标 Mistral 57x / Anthropic 21-31x 需要真正的前沿竞争力

## §13 电力交易 AI 赛道锚点（v1.7.14 美克生深挖发现——「蘑菇小美」工具分析时拉到的行业对标）

**背景**：分析美克生「蘑菇小美」（电价预测/充放电调度优化 AI 工具）时，发现电力交易 AI 已是独立赛道且有 A 股上市公司定价——这是「AI 驱动资产运营商」vs「卖 AI 服务的产品型公司」的天然对照组。

**国能日新（301162.SZ）——电力交易 AI 上市公司锚（A 级，券商研报 2026-08）**：
- 收入 7.17 亿（2025，+30.5%）、归母净利 1.30 亿（+39.2%）；2026H1 收入 3.52 亿（+9.7%）、扣非净利 0.51 亿（+17.6%）
- **电力交易产品 2026H1 仅 729 万（+57.3%）**——赛道整体极早期（美克生「电力交易零收入」不是个案）
- 商业模式：**「基础服务费 + 超额收益分成」= 三档收智慧租（outcome 定价）的电力版**——帮客户提升交易收益后分成
- 估值：2026E 净利 1.68 亿（consensus）× 43-65x 26PE（A 股）≈ 73-109 亿；隐含 PS ~8.6-12x（A 股定价）
- 产品：旷冥气象大模型 4.0 + 电力交易大模型 1.0（时空-博弈双驱动 Transformer、物理感知-博弈增强多智能体）——与美克生蘑菇小美同款能力，但**对外卖 SaaS+分成**（产品型）vs 美克生内部用（赋能型）

**赛道判据（避免再犯「AI 标签资产运营商」误判）**：
- 电力交易 AI 公司的估值锚 = 国能日新（A 股 43-65x PE / PS 8.6-12x），**不是** AI 应用矩阵任何档位——赛道处早期，先看政策放开（现货连续结算省份数）再看收入兑现
- 收入模式：基础服务费（订阅性质）+ 超额收益分成（outcome）——**「分成」是电力版三档信号**
- 资产 vs 服务分水岭：自己持有储能资产吃收益 = 资产运营商（框架外）；帮别人交易收服务费/分成 = AI 服务公司（可入框架三档雏形）
