# 定档收入结构取证 · 财报原文检索实操（v1.13.7）

> 背景：2026-09-02 **框架校准记录**：团队纠正「为什么不去找原文把定档坐实」——海致/迅策两份报告把定档关键证据（收入确认方式/Token 占比/商业模式阶段）丢进 DD Priority，靠转述猜测。这是范式「RaaS 实为探索」教训的重演。
> 铁律：**自称模式 ≠ 会计模式**。公司叙事（AI 平台/Token 化/SaaS 化）不是定档依据；会计确认的收入结构才是。

## 一、财报原文三查（定档必做）

### 查 1：收入确认时间分类（项目制 vs 订阅的分水岭）
- 中报/年报附注「按收入确认时间划分」表：**时间点确认（验收制）= 项目制；随时间推移 = 订阅/持续服务**
- **📍 短式中期业绩公告（~39 页）里该表在分部附注（note 3(b)「按收入確認時間劃分」小表，海致 32 页），不在会计政策附录**——短式公告常不含完整会计政策段，别在政策章找；从「可報告分部」附注扫起（关键词：按收入確認時間劃分 / 時間點 / 隨時間推移）
- 海致实证：时间点 2.879 亿 = **97.4%**，随时间 0.076 亿 = 2.6%（仅图谱方案有，智能体 = 0）→ 第零档·项目制 100% 坐实（此前报告已判对，但靠推断；原文把它变成硬证据）
- 顺带拿：分部收入 + 分部毛利（海致图谱 39.5% / 智能体 52.9%）、客户数/客单价（图谱 59 家 310 万 / 智能体 29 家 400 万——大项目制特征）

### 查 2：分部拆分原文（自称高增长业务的真实占比）
- 迅策自称「Token 第一股」，盈喜媒体口径暗示 Token 占比将达 20-30%
- 中报原文 17 页：「Token 业务模式**收入占比突破 10%**」——与媒体暗示差一倍
- 教训：**盈喜/管理层指引 ≠ 中报实际确认数**；媒体转述可能放大叙事

### 查 3：管理层商业模式自我表述（是否「探索中」）
- 迅策中报 26 页原文：「本集团将加速推进**从项目制、订阅制向探索按 Token 业务**……」——管理层自己承认还在迁移早期
- 同构先例：范式 Agentic 自称「RaaS」实为探索性项目
- 判断：公司说「推进/探索/布局」= 期权；说「已实现/占比达 X%」= 当期。期权不给完整估值

### 加查：KA 集中度（单客户占比）
- 迅策中报 8 页：单一客户 A 收入 2.409 亿 = 总收入 **24.9%**——KA 集中是增速持续性风险
- 附注「收入 ≥10% 单一客户」表是所有港股财报标配，一页即得

## 二、财报 PDF 获取实操（hkexnews）

1. 上市后财报走 **hkexnews 标题搜索页**（浏览器）：
   - `https://www1.hkexnews.hk/search/titlesearch.xhtml?lang=zh`（上市公司信息标题搜索）
   - 股份代号/名称下拉框输入公司名 → 选「代码+名称」行 → 设日期范围 → 搜
   - 结果按「文件」列找「公告及通告 - [中期业绩] / [末期业绩]」→ 点标题拿 PDF
   - 代码已知也可直接拼：`https://www1.hkexnews.hk/listedco/listconews/sehk/YYYY/MMDD/XXXX_c.pdf`
2. ⚠️ curl 直接打 titleSearchServlet.do 对按代码筛不可靠（stockId 是内部号非 6 位代码）；搜中文公司名会命中基石投资方公告而非标的本身——**浏览器下拉选股最稳**
3. 下载：`curl -sL -o file.pdf "<hkexnews URL>" -A "Mozilla/5.0"`
4. 检索：pymupdf 读 PDF → 关键词扫页（「時間點/隨時間」「收入確認」「按收入」→ 分部表；「佔比突破」「項目制」「訂閱制」「探索」→ 业务讨论页；「10% 或以上」→ KA 表）

## 四、报告写法联动

- 定档证据进正文（Step 1/三、商业模式定档段），**不是** DD Priority——DD Priority 只放原文真没披露的（NDR/留存拆分等）
- 索引表来源标 S 级 + URL + 「已读 PDF（关键页）」；读取状态注明检索页码
- 定档结论若靠原文坐实，写「原文实证：XX 页」——validate R8 已读标注一并满足
